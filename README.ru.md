# 🔒 P2P Chat — Зашифрованный чат без сервера

[🇬🇧 English](README.md) · [🇪🇸 Español](README.es.md) · [🇩🇪 Deutsch](README.de.md) · [🇨🇳 中文](README.zh.md) · [🇷🇺 Русский](README.ru.md)

> Одноранговый (peer-to-peer), сквозным образом зашифрованный чат, который полностью работает в вашем браузере. Никаких серверов, никаких аккаунтов, никаких логов на чьём-либо устройстве. Просто откройте страницу, поделитесь названием комнаты — и общайтесь.

---
## Что это?

**P2P Chat** — это одностраничное веб-приложение, позволяющее двум и более людям переписываться, отправлять файлы и проверять личность друг друга — **без какого-либо backend**. Нет центрального сервера, нет базы данных, нет учётных записей и нет телеметрии.

Сам браузер становится клиентом. WebRTC отвечает за прямое соединение между узлами. Web Crypto (внутри Web Worker) отвечает за шифрование. IndexedDB хранит историю локально. Всё, что вы видите в интерфейсе, строится на этих трёх компонентах.

Это Progressive Web App (PWA): её можно установить на телефон или компьютер как обычное приложение, и интерфейс работает даже без подключения к сети.

---
## Зачем?

Большинство "приватных" чат-приложений всё равно требуют доверия к оператору сервера. Даже если они заявляют о сквозном шифровании, они знают, кто, с кем и когда общается. Этот проект полностью убирает сервер из уравнения:

- **Нет backend, который можно изъять, вызвать в суд повесткой или взломать.**
- **Нет аккаунта для регистрации.**
- **Нет следа метаданных** на инфраструктуре, которую вы не контролируете (кроме сигнального слоя, см. ниже).
- **Вы можете разместить его сами** на GitHub Pages, Cloudflare Pages, Netlify или даже на флешке — это просто статические файлы.

## Возможности

### Основное
- **Одноранговый (P2P) чат** поверх каналов данных WebRTC.
- **Опциональное сквозное шифрование** AES-GCM (256 бит), ключ выводится из общего пароля через PBKDF2 (200 000 итераций, SHA-256).
- **Автоматическая ротация ключей каждые 24 часа** — старые ключи сообщений устаревают; новые выводятся из того же пароля с использованием вращающегося слота.
- **Несколько комнат во вкладках** — можно открывать и вести сразу несколько бесед.
- **Сохраняющаяся история** в IndexedDB (для каждой комнаты, на каждом устройстве отдельно).
- **Очередь сообщений** — сообщения, отправленные оффлайн-собеседнику, сохраняются локально и доставляются при его повторном подключении.
- **Отметки о доставке** — ✓ отправлено, ✓✓ доставлено.
- **Удалённое удаление сообщений** — можно удалить сообщение только у себя или у всех, кому оно было доставлено.
- **Передача файлов и изображений** — по частям, через тот же зашифрованный канал данных.
- **Опция не сохранять файлы** в истории (хранится только имя файла).

### Безопасность и идентификация
- **Внеполосная (out-of-band) проверка SAS** — 6-значный код, полученный из обмена по ECDH (P-256), позволяющий убедиться в отсутствии атаки "человек посередине".
- **Опциональная блокировка PIN-кодом** с автоблокировкой при бездействии.
- **Отпечаток**, отображаемый в интерфейсе, чтобы собеседники могли проверить вас при первом контакте.
- **Список контактов**, хранящийся локально.

### Удобство использования
- **Устанавливаемое PWA** с офлайн-оболочкой интерфейса.
- **Многоязычный интерфейс**: испанский, английский, немецкий, китайский, русский.
- **Тёмная / светлая / системная темы** и **три размера шрифта**.
- **Виртуальная прокрутка** — плавно обрабатывает тысячи сообщений.
- **Сетевая статистика** — отправленные/полученные байты, RTT, тип соединения (прямое или через релей).
- **Внутренние логи** — с фильтрацией по категориям (соединение, ICE, сообщения).
- **Панель диагностики** с полным внутренним состоянием для устранения неполадок.
- **Действия для переподключения** — перезапуск соединений, очистка кэша сигнализации, полный сброс.

## Как пользоваться

1. Откройте развёрнутый URL (или запустите локально, см. ниже).
2. Нажмите **＋**, чтобы создать чат.
3. Выберите **название комнаты** и, при желании, **пароль**.
   - Без пароля: соединение всё равно зашифровано (DTLS), но дополнительного слоя E2E-шифрования нет.
   - С паролем: добавляется дополнительный слой AES-GCM, а сигнальные сообщения (SDP) также шифруются, что предотвращает MITM-атаку на уровне сигнализации.
4. Поделитесь названием комнаты (и паролем — по *другому* защищённому каналу) с собеседником.
5. Начните общение. Файлы можно перетащить в окно или прикрепить кнопкой 📎.

### Проверка личности

После установления соединения нажмите на собеседника в строке состояния → **Показать SAS**. Сравните 6-значный код с собеседником по отдельному каналу (лично, через Signal, по телефону). Если код совпадает, нажмите **Сохранить и подтвердить**.

## Как это работает

```
┌────────────────┐                          ┌────────────────┐
│  Браузер A      │                          │  Браузер B      │
│                 │                          │                 │
│  ┌──────────┐   │                          │  ┌──────────┐   │
│  │ P2P Chat │   │◄────────────────────────►│  │ P2P Chat │   │
│  └──────────┘   │      WebRTC (DTLS)       │  └──────────┘   │
│     ▲     ▲     │                          │     ▲     ▲     │
│     │     │      │                          │     │     │      │
│    UI   Crypto  │                          │    UI   Crypto  │
│         Worker  │                          │         Worker  │
└────┬────────────┘                          └───────────┬────┘
     │                                                    │
     └────────────► Сигнализация ◄─────────────────────────┘
          (BitTorrent-трекеры / Nostr / MQTT)
```

1. **Сигнализация**: два браузера находят друг друга через публичную децентрализованную сеть — по умолчанию через BitTorrent-трекеры, с Nostr и MQTT в качестве резервных вариантов. Если установлен пароль, сообщения SDP (содержащие DTLS-отпечатки) шифруются перед отправкой, поэтому вредоносный узел сигнализации не может провести атаку MITM.
2. **Соединение**: WebRTC согласовывает прямое одноранговое соединение. Если сеть блокирует прямой путь (например, оба узла находятся за CGNAT), трафик передаётся через TURN-сервер — по-прежнему со сквозным шифрованием, но с большей задержкой.
3. **Шифрование**: WebRTC всегда шифрует данные с помощью DTLS-SRTP. Если вы установили пароль, внутри канала данных дополнительно применяется слой AES-GCM, а ключ обновляется каждые 24 часа.
4. **Хранение**: сообщения и файлы хранятся локально в IndexedDB, зашифрованные при хранении, если установлен пароль.
5. **Сохранение состояния**: при перезагрузке приложение восстанавливает ваши комнаты и подключается автоматически.

## Безопасность и приватность

**Что защищено:**
- Содержимое сообщений (DTLS — всегда; AES-GCM — при установленном пароле).
- Содержимое сигнализации (SDP), если установлен пароль.
- Файлы (так же, как и сообщения).
- Локальная история при хранении (если установлен пароль).

**Что не защищено:**
- **Ваш IP-адрес виден** собеседнику при прямом соединении. Это заложено в самой природе WebRTC. Если соединение идёт через релей (TURN), собеседник видит IP релея, но оператор TURN видит ваш реальный IP.
- **Слой сигнализации** (BitTorrent-трекеры, Nostr-релеи, MQTT-брокеры) видит, что два IP-адреса пытаются соединиться, если только вы не установили пароль (в этом случае он не может прочитать SDP, но всё равно видит саму попытку соединения).
- **Нет forward secrecy** сверх того, что обеспечивает DTLS. Если злоумышленник получит ваш пароль *и* вашу базу IndexedDB, он сможет расшифровать сохранённые сообщения текущего слота ключа (окно в 24 часа).

**Модель угроз**: это приложение разработано для защиты от пассивного наблюдения за сетью и от оператора сервиса, желающего читать ваши переписки. Оно *не* предназначено для защиты от скомпрометированного устройства, глобального противника с возможностью корреляции трафика, или собеседника, который намеренно сливает ваши переписки.

**Рекомендации:**
- Всегда устанавливайте надёжный, случайный пароль.
- Передавайте его по другому каналу (Signal, лично).
- Проверяйте SAS.
- Используйте VPN, если не хотите, чтобы собеседник видел ваш IP.

## Ограничения

- **В некоторых сетях требуется релей (TURN)** (~15–20% соединений, особенно на мобильных сетях/CGNAT). По умолчанию приложение использует бесплатные публичные TURN-серверы, работающие по принципу "как получится" и иногда медленные.
- **Нет доставки в офлайне**: если собеседник офлайн в момент отправки, сообщение остаётся в локальной очереди и доставляется при его повторном подключении. Никакой сервер его для него не хранит.
- **Нет push-уведомлений**, когда вкладка закрыта. Уведомления на рабочем столе работают, только пока страница открыта в фоне.
- **Нет синхронизации между устройствами**: у каждого устройства своя собственная история. Без сервера синхронизировать телефон и ноутбук невозможно.
- **Ограничения локального хранилища**: браузеры на мобильных устройствах обычно ограничивают IndexedDB примерно 50 МБ. Крупные файлы быстро его заполнят; отключите "Сохранять файлы в историю", если они вам не нужны.
- **Слой сигнализации публичен**: трекеры и релеи — это общая инфраструктура. Если они недоступны, приложение не сможет найти собеседников. Попробуйте другую стратегию (Nostr, MQTT) или разверните собственный coturn.

## Развёртывание

### GitHub Pages (рекомендуется)

1. Склонируйте или сделайте форк этого репозитория.
2. Убедитесь, что в корне находятся файлы: `index.html`, `app.js`, `i18n.js`, `sw.js`, `manifest.json`, `icon.svg`, а также папка `modules/`.
3. Включите GitHub Pages в **Settings → Pages → Source: main branch / root**.
4. Готово. HTTPS предоставляется GitHub.

### Любой статический хостинг

Поскольку backend отсутствует, подойдёт любой статический хостинг: Cloudflare Pages, Netlify, Vercel, обычный nginx, S3-бакет, Raspberry Pi с `python -m http.server`.

### Локальная разработка

```bash
# Подойдёт любой статический сервер. Например:
python3 -m http.server 8080
# Затем откройте http://localhost:8080
```

> Важно: crypto.subtle, navigator.clipboard, уведомления и service workers требуют HTTPS или localhost. Открытие index.html через file:// нарушит работу некоторых функций.

## Модули
Три файла в modules/ (кроме crypto.worker.js) собираются с помощью esbuild из Trystero. Чтобы пересобрать их:
```bash
npm install --save-dev trystero@0.21.6 esbuild
mkdir -p modules
for strat in torrent nostr mqtt; do
  echo "export * from 'trystero/$strat'" > .entry.js
  npx esbuild .entry.js --bundle --format=esm --target=es2022 \
    --platform=browser --outfile=modules/trystero-$strat.js
done
rm .entry.js
rm -rf node_modules package.json package-lock.json
```

## Технологический стек
- Чистый JavaScript (ES-модули), без фреймворков.
- WebRTC для однорангового транспорта.
- Trystero для сигнализации через BitTorrent, Nostr и MQTT.
- Web Crypto API (внутри Web Worker) для AES-GCM, PBKDF2, ECDH, SHA-256.
- IndexedDB для локального хранения.
- Service Worker для офлайн-оболочки PWA.
- Отсутствие шага сборки для самого приложения.
